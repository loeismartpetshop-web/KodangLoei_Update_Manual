01

บทนำ & ภาพรวมระบบ

เว็บนี้ใช้ทำอะไร

KodangLoeiSmartpetshop เป็นระบบร้านขายอาหารและสินค้าสัตว์เลี้ยงแบบครบวงจร ลูกค้าสั่งซื้อผ่านเว็บ รับบิลและติดตามสถานะผ่าน LINE ส่วนแอดมินจัดการสินค้า ออเดอร์ การเงิน หน้าตาเว็บ และข้อความบอทได้จากระบบหลังบ้านในหน้าเดียว

เหมาะกับใคร

ลูกค้า
เลือกซื้อสินค้า ชำระเงิน รับบิลและเช็กสถานะใน LINE
แอดมินร้าน
รับออเดอร์ เปลี่ยนสถานะ ยืนยันการจ่าย เคลียร์ออเดอร์ ตั้งค่าทุกอย่าง
เจ้าของร้าน
ดูยอดขายวัน/สัปดาห์/เดือน/ปี และสรุปยอดรายเดือนใน Google Sheets

4 ส่วนหลักของระบบ

  1. เว็บร้านค้า — หน้าสำหรับลูกค้าเลือกซื้อสินค้า
  2. ระบบหลังบ้าน — อยู่ในไฟล์เดียวกับเว็บ (เข้าผ่านแอดมิน) มี 5 เมนู: Dashboard, สินค้า, ออเดอร์, ตั้งค่า, บอท
  3. LINE OA / LIFF / Bot — ส่งการ์ดบิล ตอบข้อความ Rich Menu และหน้าสถานะออเดอร์
  4. Google Sheets + Supabase — ฐานข้อมูลออเดอร์/สินค้า/ตั้งค่า และสรุปยอดรายเดือน

ภาพรวม Flow การสั่งซื้อ

ขั้นเกิดอะไรขึ้น
1ลูกค้าเข้าเว็บ → เลือกสินค้า → ใส่ตะกร้า
2เลือกวิธีรับ/ชำระเงิน → กรอกข้อมูล → ส่งคำสั่งซื้อ
3ระบบบันทึกเข้า Google Sheets / Supabase
4LINE bot ส่งการ์ดบิลให้ลูกค้า (ถ้ามี LINE userId)
5ลูกค้ากดดูสถานะผ่าน LIFF
6แอดมินจัดการสถานะในหลังบ้าน
7เมื่อส่งแล้ว+จ่ายแล้ว แอดมินเคลียร์ออเดอร์เข้า Orders_Archive
8Dashboard และสรุปเดือน ยังนับยอดจากออเดอร์ที่จ่ายแล้ว (Orders + Archive)
🔑 หลักสำคัญที่ต้องจำ 3 ข้อ

1) Bank/QR = จ่ายแล้วทันที · COD = ยังไม่จ่าย จนกว่าแอดมินกดยืนยัน
2) เคลียร์ออเดอร์ ≠ ยอดหาย — ออเดอร์ที่เคลียร์ไปอยู่ Orders_Archive ยังถูกนับยอด
3) ยอดขายใน Dashboard นับเฉพาะ Payment Status = จ่ายแล้ว และ ไม่ถูกยกเลิก

02

คู่มือลูกค้า

ส่วนนี้สำหรับลูกค้า อธิบายตั้งแต่เข้าเว็บจนถึงติดตามสถานะใน LINE

2.1 เข้าเว็บร้านค้า

  1. เปิดลิงก์เว็บร้าน — จะเห็นหน้าโหลด (Splash Screen) โลโก้ร้านขึ้นก่อน
  2. อาจมีรูปโปรโมชั่นเต็มจอ เด้งขึ้นมา กดปิดเพื่อเข้าหน้าร้าน
  3. เข้าสู่หน้าร้าน เห็นโลโก้มุมบนซ้าย เมนู หมวดหมู่สินค้า ▾ และปุ่ม ตะกร้าสินค้า
[ ภาพหน้าจอ: หน้าร้านค้า ]ใส่ภาพหน้าแรกของเว็บ ชี้ตำแหน่งปุ่มตะกร้า (มุมบนขวา) และเมนูหมวดหมู่

2.2 เลือกสินค้า

  • กดปุ่ม หมวดหมู่สินค้า ▾ เพื่อกรองสินค้าตามหมวด
  • แต่ละสินค้ามีปุ่ม ใส่ตะกร้า และปุ่ม สั่งซื้อ (สั่งทันที)
  • ถ้าสินค้าอยู่ในตะกร้าครบจำนวนแล้ว ปุ่มจะขึ้นว่า อยู่ในตะกร้าครบแล้ว

2.3 ตะกร้าสินค้า

กดปุ่ม ตะกร้าสินค้า เพื่อดูรายการ ปรับจำนวน หรือลบสินค้า จากนั้นกด ชำระเงิน เพื่อไป Checkout (ถ้าตะกร้าว่างจะขึ้นว่า "ตะกร้าว่างเปล่า")

2.4 Checkout — กรอกข้อมูลและเลือกวิธีชำระเงิน

หน้านี้ลูกค้ากรอกข้อมูลจัดส่งและเลือกวิธีชำระเงิน

ข้อมูลที่ต้องกรอก

  • ลูกค้าประจำ: ถ้ามีรหัสร้านในชีต Customers ให้กรอกรหัสก่อนส่งคำสั่งซื้อ
  • จัดส่ง: กรอกชื่อ เบอร์โทร ที่อยู่ / หรือเลือก รับที่ร้าน (เตรียมรหัสคำสั่งซื้อไปยืนยันกับพนักงาน)

วิธีชำระเงิน

วิธีความหมายสถานะจ่ายเงินเริ่มต้น
โอนผ่านธนาคารเลือกบัญชีที่ร้านตั้งไว้ แล้วโอนจ่ายแล้ว
สแกน QRสแกนจ่ายด้วย QR ที่ร้านตั้งไว้จ่ายแล้ว
COD เก็บเงินปลายทางชำระเงินสดเมื่อได้รับ/มารับสินค้า ไม่ต้องแนบสลิปยังไม่จ่าย
ℹ️ ทำไม Bank/QR ถึงเป็น "จ่ายแล้ว" ทันที

เพราะลูกค้าต้องชำระออนไลน์ก่อน ระบบจึงถือว่าจ่ายแล้ว — ส่วน COD จะนับเป็นยอดขายก็ต่อเมื่อแอดมินกดยืนยันภายหลัง

2.5 ส่งคำสั่งซื้อ

  1. ตรวจ สรุปคำสั่งซื้อ ให้ครบถ้วน
  2. กดปุ่ม ส่งคำสั่งซื้อ (ระหว่างส่งจะขึ้น "กำลังส่งคำสั่งซื้อ")
  3. ถ้าสต็อกไม่พอ ระบบจะแจ้ง "สั่งซื้อไม่สำเร็จ — สต็อกไม่เพียงพอ" ให้ปรับจำนวนแล้วลองใหม่

2.6 รับบิลและดูสถานะใน LINE

  • ถ้าลูกค้าเปิดผ่าน LINE/LIFF ระบบจะ push การ์ดบิลสั่งซื้อ ให้ทันที (ชื่อร้าน, Order ID, รายการ, ยอดรวม, วิธีชำระ, วันที่, สถานะ)
  • ถ้าเลือก COD จะมีข้อความเตือนเตรียมเงินปลายทางตามมาหลังการ์ดบิล
  • กดปุ่ม ดูสถานะออเดอร์ บนการ์ด → เปิดหน้า LIFF กลางจอ LINE
[ ภาพหน้าจอ: การ์ดบิลใน LINE ]ใส่ภาพการ์ดบิลที่ลูกค้าได้รับ พร้อมปุ่ม "ดูสถานะออเดอร์"

2.7 หน้าสถานะออเดอร์ (LIFF)

หน้านี้แสดงโลโก้ร้าน, Order ID, สถานะปัจจุบัน, Timeline, รายการสินค้า, ยอดรวม และวิธีชำระเงิน โดยอัปเดต เรียลไทม์ — ถ้าแอดมินเปลี่ยนสถานะ หน้าจะเปลี่ยนทันทีโดยไม่ต้องรีโหลด (มุมขวาบนเห็นจุด ● LIVE สีเขียว)

Timeline 4 ขั้น

ออเดอร์ใหม่→ รอคอนเฟิร์ม→ กำลังจัดส่ง→ ส่งแล้ว

เมื่อส่งครบทั้ง flow จุดและเส้นทั้งหมดเป็นสีเขียว ส่วนขั้นที่ยังไม่ถึงเป็นสีเทา

2.8 ยกเลิกออเดอร์

⚠️ ลูกค้ายกเลิกเองได้เฉพาะ 2 สถานะ

ยกเลิกเองได้เมื่อสถานะเป็น ออเดอร์ใหม่ หรือ รอคอนเฟิร์ม เท่านั้น
ถ้าเป็น กำลังจัดส่ง หรือ ส่งแล้ว แล้ว จะกดยกเลิกเองไม่ได้

เมื่อยกเลิกสำเร็จ ระบบจะเปลี่ยนสถานะเป็นยกเลิก บันทึกเหตุผล และ push การ์ดแจ้งยกเลิก (การ์ดแดง) กลับไปใน LINE

2.9 Rich Menu ใน LINE

  • เช็คสถานะออเดอร์ — บอทจะให้พิมพ์เบอร์โทร 10 หลัก แล้วค้นออเดอร์ให้ (เพราะ Order ID ผูกเลขท้ายเบอร์ไว้ จึงเจอออเดอร์ของเบอร์เดียวกันได้ครบ แม้สั่งคนละวัน — ดูโครงสร้างรหัสในบท 5.1)
  • ติดต่อแอดมิน — บอทแจ้งให้พิมพ์รายละเอียด แล้วแอดมินจะตอบกลับ

04

จัดการสินค้า

เมนู สินค้า ในหลังบ้าน หน้าจัดการสินค้าและหมวดหมู่ มีแถบหมวดหมู่ด้านซ้าย (sidebar) และเนื้อหาด้านขวา

4.1 สิ่งที่ทำได้

เพิ่ม / แก้ไข / ลบสินค้า
จัดการรายการสินค้าทั้งหมด
ตั้งราคา · ตั้งสต๊อก
กำหนดราคาและจำนวนคงเหลือ
ใส่รูปสินค้า
อัปโหลดรูปประกอบ

เพิ่มหมวดหมู่หลัก / ปรับชื่อ / ข้อความบนปุ่มสั่งซื้อ

4.2 หมวดหมู่

  1. กด + เพิ่มหมวดหมู่หลัก เพื่อสร้างหมวดแรก (ถ้ายังไม่มีจะขึ้น "ยังไม่มีหมวดหมู่")
  2. เลือกหมวดหมู่ทางซ้ายเพื่อแก้ไข — ตั้ง ชื่อหมวดหมู่ และ ข้อความบนปุ่มสั่งซื้อ
ℹ️ การบันทึก

สินค้าและหมวดหมู่ใช้ปุ่ม บันทึกทั้งหมด (ไม่ใช่ปุ่มบันทึกธีม) หลังบันทึกระบบจะ sync กับ Supabase

05

จัดการออเดอร์

เมนู ออเดอร์ มีช่องค้นหา ปุ่มกรองสถานะ และรายการออเดอร์ทางซ้าย เมื่อกดออเดอร์จะเห็นรายละเอียดทางขวา

5.1 โครงสร้างรหัสออเดอร์ (Order ID)

ระบบสร้าง Order ID ให้อัตโนมัติแบบ เรียลไทม์ ตอนลูกค้ากดสั่งซื้อ มี 2 รูปแบบตามประเภทลูกค้า แต่ใช้โครงเดียวกัน:

CUS-[รหัสร้าน]-[เลขท้ายเบอร์ 4 ตัว]-[วันเดือนปี 6 หลัก]-[สุ่ม 3 ตัว]

ส่วนความหมายตัวอย่าง
CUS-ขึ้นต้นทุกออเดอร์CUS-
รหัสร้านลูกค้าทั่วไป = KDL (คงที่) · ลูกค้าประจำ = รหัสร้านของลูกค้าKDL หรือ C001
เลขท้ายเบอร์ 4 ตัว4 ตัวท้ายเบอร์โทรของลูกค้า3344
วันเดือนปี 6 หลักDD MM YY (ปี พ.ศ. 2 หลัก, เวลาไทย) ตามวันที่ลูกค้าสั่งจริง310569 = 31 พ.ค. 69
สุ่ม 3 ตัวสุ่มกันรหัสซ้ำ (เป็นตัวเลขหรือตัวอักษร)120 หรือ X7Q

ตัวอย่างจริง

  • ลูกค้าทั่วไป: CUS-KDL-3344-310569-120
  • ลูกค้าประจำ: CUS-C001-3344-310569-120 — เหมือนลูกค้าทั่วไปทุกอย่าง ต่างแค่ช่องรหัสร้านเปลี่ยนจาก KDL เป็นรหัสร้านของลูกค้า (เช่น C001, C0000)
🔑 ทำไมต้องมีเลขท้ายเบอร์ + สุ่ม 3 ตัว

เลขท้ายเบอร์ 4 ตัว — เวลาลูกค้าเช็คออเดอร์ จะพิมพ์เบอร์โทร ระบบจึงดึงออเดอร์ที่ผูกเบอร์เดียวกันมาให้ครบ ลูกค้า 1 คนที่สั่งไว้หลายออเดอร์คนละวันก็เจอครบในครั้งเดียว
สุ่ม 3 ตัวท้าย — กันรหัสซ้ำ เผื่อเบอร์เดิมสั่งหลายครั้ง (แม้วันเดียวกันก็ไม่ชนกัน)

ℹ️ กรณีไม่มีเบอร์โทร

ถ้าออเดอร์ไม่มีเบอร์ครบ (น้อยกว่า 4 หลัก) ระบบจะเปลี่ยนไปใช้รหัสสำรองแบบสุ่ม (ขึ้นต้น CUS- ตามด้วยรหัสเวลา+สุ่ม) แทนโดยอัตโนมัติ

5.2 ค้นหาและกรอง

  • ช่องค้นหา: พิมพ์ Order ID / ชื่อ / เบอร์โทร

5.6 เคลียร์เป็นชุด

🔑 เคลียร์ออเดอร์คืออะไร

คือการ ย้ายสำเนาเข้า Orders_Archive แล้วลบออกจาก Orders — ยอดขายจริงยังถูกนับอยู่ ไม่หายไปไหน ส่วนออเดอร์ทดสอบที่ไม่อยากให้นับยอด ต้องลบด้วยเมนูพิเศษใน Google Sheets (ดูบทที่ 8)

บอท LINE & Rich Menu

เมนู บอท ใช้ตั้งค่าบอทตอบกลับอัตโนมัติ (ทำงานผ่าน LINE Webhook) — ข้อความพิเศษอยู่บนสุดและทำงานก่อนกฎทั่วไป

7.1 ข้อความพิเศษ 3 กล่อง

กล่องหน้าที่ตั้งค่าได้
แจ้งเตือน CODเด้งตามหลังการ์ดบิลเมื่อลูกค้าเลือก CODเปิด/ปิด + ข้อความเตือน
Rich Menu เช็คออเดอร์ลูกค้ากด Rich Menu → บอทขอเบอร์โทรเปิด/ปิด + ข้อความ trigger + ข้อความตอบกลับ
Rich Menu ติดต่อแอดมินลูกค้ากด Rich Menu → บอทตอบให้พิมพ์รายละเอียดเปิด/ปิด + ข้อความ trigger + ข้อความตอบกลับ

7.2 กฎบอททั่วไป

กด + เพิ่มคีย์เวิร์ดใหม่ เพื่อสร้างกลุ่มตอบกลับ — ตั้งชื่อกลุ่ม, เลือกตอบทุกข้อความ/ตอบตามคีย์เวิร์ด, ใส่คีย์เวิร์ดได้หลายคำ และข้อความตอบกลับ (มี preview บน mockup LINE ให้ดู)

⚠️ Rich Menu ต้องตรงเป๊ะ (exact match)

ข้อความที่ Rich Menu ส่งเข้ามา ต้องตรงกับช่อง trigger ในหลังบ้าน ทุกตัวอักษร เช่น ถ้าหลังบ้านใส่ ติดต่อแอดมิน แต่ Rich Menu ส่ง ติดต่อแอดมินค่ะ จะไม่ match — และควรตั้ง Rich Menu action เป็นแบบ "ข้อความ"

FAQ / แก้ปัญหา

อาการสาเหตุ / วิธีแก้
บิลไม่เด้งใน LINEลูกค้าไม่ได้เปิดผ่าน LINE (ไม่มี lineUserId), ปิด auto push, หรือ push ไม่สำเร็จ
ยอดไม่เข้ารายเดือนยังไม่ refresh → ใช้เมนู "รีเฟรชสรุปยอดทั้งหมด"
COD ถูกนับยอดเร็วเกินไปเช็ก Payment Status — COD ต้องเป็น "จ่ายแล้ว" ก่อนถึงนับ ถ้านับเร็วแปลว่ากดยืนยันไปแล้ว
Rich Menu ไม่ตอบข้อความ Rich Menu ไม่ตรงกับ trigger ในหลังบ้าน (ต้อง exact match)
สีการ์ดไม่เปลี่ยนยังไม่กด "บันทึกธีมเท่านั้น"
ลูกค้ายกเลิกไม่ได้สถานะเลย "รอคอนเฟิร์ม" ไปแล้ว (เป็นกำลังจัดส่ง/ส่งแล้ว) — ยกเลิกเองไม่ได้
Dashboard ไม่ refreshกด SYNC NOW หรือเปิด Realtime ใน Supabase
ยอดยังค้างหลังลบ rowออเดอร์ยังอยู่ใน Orders_Archive → ใช้เมนู "ลบออเดอร์ด้วย Order ID"
✓

เช็กลิสต์ทดสอบระบบก่อนใช้จริง

ทดสอบออเดอร์ Bank/QR

  1. สั่งซื้อผ่านเว็บ เลือก Bank หรือ QR
  2. เช็กใน Orders ว่า Payment Status = จ่ายแล้ว
  3. เช็กว่า LINE ได้การ์ดบิล และเปิดหน้าสถานะได้
  4. เปลี่ยนสถานะเป็น "ส่งแล้ว" → เคลียร์เข้า Archive
  5. เช็ก Dashboard รายเดือนว่ายังนับยอด

ทดสอบออเดอร์ COD

  1. สั่งซื้อ เลือก COD → Payment Status = ยังไม่จ่าย
  2. เช็กว่า LINE ได้การ์ดบิล + ข้อความเตือน COD
  3. Dashboard ยังไม่ควรนับยอด
  4. แอดมินกด "จ่ายแล้ว" → Dashboard จึงนับยอด
  5. เปลี่ยนเป็น "ส่งแล้ว" → เคลียร์เข้า Archive → ยอดยังอยู่

ทดสอบยกเลิก

  1. สั่งออเดอร์ใหม่ → เปิดหน้า LIFF → กดยกเลิกขณะยังอนุญาต
  2. เช็ก Orders ว่าสถานะเป็นยกเลิก + LINE มีการ์ดยกเลิก
  3. เช็ก Dashboard ว่าไม่นับยอด

ทดสอบ Rich Menu

  1. ตั้ง Rich Menu action เป็นข้อความ เช็คสถานะออเดอร์ → กดใน LINE → บอทให้พิมพ์เบอร์ → พิมพ์เบอร์ → บอทส่งรายการออเดอร์
  2. ตั้ง Rich Menu action เป็นข้อความ ติดต่อแอดมิน → กดใน LINE → บอทตอบข้อความติดต่อแอดมิน

ทดสอบ UI บนมือถือ

  • เปิดหลังบ้านบนมือถือ — กล่องตั้งค่าสีไม่ซ้อนกัน, ปุ่มบันทึกไม่ทับ input
  • การ์ดตัวอย่างยังอ่านได้, ช่องเลือกสี/hex ไม่ทับ label
